me-bricks

Kit de web components do Minha Escala para protótipos — sem build, sem dependências, só HTML.

Componentes encapsulados em Shadow DOM que espelham o visual do aplicativo real, estilizados por design tokens (--me-*) e com API inspirada no Web Awesome: eixos variant/appearance/size, slots start/end e participação nativa em formulários.

Instalação rápida

Cole isto no <head> e todas as tags <me-*> ficam disponíveis:

<!-- 1. Design tokens (cores, tipografia, fonte Inter e ícones MDI) -->
<link rel="stylesheet" href="https://cdn.jsdelivr.net/gh/FelipeSilveiraBNG/bricks@v0.5.5/tokens.css" />

<!-- 2. Componentes (registra todas as tags <me-*>) -->
<script type="module" src="https://cdn.jsdelivr.net/gh/FelipeSilveiraBNG/bricks@v0.5.5/components/index.js"></script>

<!-- 3. Base do body (a fonte tem fallback: se o tokens.css falhar, não cai em Times New Roman) -->
<style>
  body {
    margin: 0;
    font-family: var(--me-font-family, 'Inter', system-ui, -apple-system, sans-serif);
    color: var(--me-color-text, #16161D);
    background: var(--me-color-page, #FAFAFA);
    letter-spacing: var(--me-letter-spacing, 0.5px);
  }
</style>

Funciona em editores de HTML online (as URLs são absolutas) — nunca use caminhos relativos como ./components/index.js fora deste repositório. A versão fica travada na tag @v0.5.5. Ao subir um release novo, rode node tools/release.mjs <versão> em vez de editar à mão — a versão aparece em 12 lugares e o CI recusa docs em desacordo com a tag publicada.

Se as tags <me-*> aparecerem como texto cru sem estilo, o components/index.js não carregou — confira o console: um único 404 no grafo de módulos impede o registro de todos os componentes.

Pronto — qualquer tag do kit já funciona no seu HTML:

<me-button>Candidatar-se</me-button>
<me-badge variant="success">Extra</me-badge>
Candidatar-se Extra ← renderizados ao vivo por este próprio tutorial

Design tokens

Todos os tokens de tokens.css (--me-*), agrupados por família. Valores lidos ao vivo do CSS.

<me-icon> — Ícones (MDI via CDN)

Webfont @mdi/font importada pelo tokens.css. Catálogo completo em pictogrammers.com. Tamanho/cor herdam de font-size/color.

<me-button> — Botões

Espelha os botões do app: primário = FilledButton (fundo #3CA2B9, hover teal escuro) · secundário = OutlineButton (borda 2px) · terciário = GhostButton · variant="danger" = PolarButton (hovers próprios). Tipografia semibold 14px, radius 4px em todos.

<me-modal> — Modal

Espelha o Modal.vue do app — o componente mais usado do design system deles (98 arquivos o consomem) — sobre o <dialog> nativo. Spec medida no Storybook e na demo do PRD32: backdrop #111827 a 50%, caixa radius 8px com max-height: 90vh, header 24/24/16 com título 20px/28px, corpo 16/24 rolável, footer 16/24, bordas opcionais de 2px, botão fechar 40×40 em 16/16.

Por que o <dialog> nativo e não um overlay à mão como no app: ele abre no top layer, então um me-select ou me-dropdown de dentro do modal flutua por cima dele sem escada de z-index — a demo do PRD32 precisou manter uma à mão (overlay 80 / modal 90 / popovers 100) exatamente por isso. E vêm de graça o focus trap, o inert no resto da página e o Esc, que o Modal.vue do app não tem.

Tamanhos e variações

size="small" = 448px (o "modal de filtro" do app), default = 896px (max-w-4xl), size="large" = 80vw. Para um valor próprio, use --me-modal-width. Também há without-header, without-close-button, no-body-padding, max-height (default 90vh) e min-height.

Fechar é sempre cancelável

O ×, o clique no overlay, o Esc e o hide() passam **todos** pelo mesmo evento me-close, que é cancelável e informa a origem em detail.source (close-button | overlay | escape | api). Fechar pelo overlay é o default, como no app — quem precisa proteger um formulário barra pela origem. 

<script>
  modal.addEventListener('me-close', (e) => {
    if (e.detail.source !== 'close-button' && temAlteracao) e.preventDefault();
  });
</script>

O corpo é quem rola (header e footer ficam parados) e a rolagem da página fica travada enquanto houver modal aberto — com contador, para modais empilhados. O foco vai para dentro do modal na abertura; ponha autofocus num elemento para escolher qual. Isso não é refinamento: medimos que sem foco dentro do diálogo o Esc nativo não dispara.

<me-select> + <me-select-option> — Campo de seleção

Espelha o SubjectsAutocomplete.vue do app (v-autocomplete outlined, density compact). A aparência foi medida nos estilos computados do Storybook: chip pílula de 26px com fonte 12px e fundo = marca a 12% sem borda; opção de 48px com ícone 24px, título 16px/24px e subtítulo 14px/16px; painel radius 4px, max-height 300px, encostado no campo.

É um campo de formulário: tem valor, entra no FormData e valida. Com multiple, cada chip vira uma entrada com o mesmo name. Para menu de ações use o me-dropdown; para pílula de filtro fora de formulário, o me-select-filter.

A seleção inicial se declara com selected na opção — não existe atributo value no me-select, porque com multiple ele exigiria uma convenção de separador e duas fontes de verdade disputando na inicialização.

Busca no servidor

Com filter="manual" o componente para de filtrar sozinho e apenas emite me-search (detail.term) — é o equivalente do :custom-filter="() => true" + update:search que o app usa. Cabe ao consumidor buscar e trocar as me-select-option. 

<me-select label="Médico" searchable filter="manual" loading id="remoto"></me-select>
<script>
  remoto.addEventListener('me-search', async (e) => {
    remoto.loading = true;
    const itens = await buscar(e.detail.term);
    remoto.replaceChildren(...itens.map(criarOption));
    remoto.loading = false;
  });
</script>

Teclado

↓/↑/Enter abrem o painel e movem a opção ativa (pulando escondidas pelo filtro e desabilitadas), Enter escolhe, Esc fecha — ou limpa a busca, se o painel já estiver fechado. Com multiple, Backspace com a busca vazia remove o último chip. Home/End só navegam a lista quando não há texto digitado: com texto, elas pertencem ao cursor do campo.

<me-dropdown> + <me-dropdown-item> — Menu de ações

Menu para disparar comandos — três pontinhos, menu de linha de tabela, menu do avatar. Funcionalidade espelhada no wa-dropdown; aparência dos itens medida no v-list-item do app (linha de 48px, ícone 24px, título 16px/24px, subtítulo 14px/16px).

Não é um campo. Não tem valor, não participa de <form>, não guarda seleção: clica, dispara, fecha. Para pílula de filtro use o me-select-filter.

O painel abre no top layer (atributo popover nativo + CSS anchor positioning), então não é recortado por ancestral com overflow — problema medido no painel do me-select-filter, ver test/panel-clipping.html. Vira para cima quando falta espaço embaixo, fecha por clique fora e Esc, e só um menu fica aberto por vez na página.

Menu completo

Ícone no slot icon, segunda linha no slot description, atalho no slot details. type="checkbox" faz item de marcar e variant="danger" faz a ação destrutiva. As colunas de marca e de ícone são reservadas no menu inteiro, então os rótulos alinham mesmo num menu misto.

Teclado

No trigger: ↓/Enter/Espaço abre e foca o primeiro item, ↑ abre e foca o último. No painel: ↑↓ andam (envolvendo nas pontas e pulando desabilitados), Home/End vão às pontas, digitar faz busca por prefixo, Enter/Espaço acionam, Esc fecha e devolve o foco ao trigger.

Eventos

me-select (detail: { value, item }) a cada item acionado — é cancelável: preventDefault() mantém o menu aberto, útil em item type="checkbox". me-toggle (detail: { open }) ao abrir/fechar, inclusive quando o fechamento vem do clique fora. 

<script>
  menu.addEventListener('me-select', (e) => {
    console.log(e.detail.value);
    if (e.detail.item.type === 'checkbox') e.preventDefault(); // não fecha
  });
</script>

<me-pagination> — Paginação

Funcionamento inspirado na TOAST UI Pagination (JS puro) e janela de páginas com reticências igual ao v-pagination do app, cuja aparência também espelha (número ativo em teal, botões arredondados, setas ‹ › nas pontas). Define-se o total por total-pages ou por total-items + items-per-page.

Básico

page é a página atual (refletida); visible-pages limita quantos números aparecem antes de truncar com reticências. Navegar emite change (detail.page); o componente cuida do próprio estado.

Página atual: 1 
<me-pagination total-pages="20" page="1" visible-pages="5"></me-pagination>

<script>
  pag.addEventListener('change', (e) => console.log(e.detail.page));
</script>

Por total de itens (estilo TOAST UI)

Em vez de total-pages, informe total-items e items-per-page — o total de páginas é calculado (ceil(total-items / items-per-page)). 

<me-pagination total-items="95" items-per-page="10"></me-pagination>

Com primeira/última (« »)

O atributo first-last adiciona os botões de ir para a primeira e a última página. Use disabled para desativar toda a navegação. 

<me-pagination total-pages="20" page="10" first-last></me-pagination>

Métodos e evento cancelável

Paridade com a TOAST UI: movePageTo(n), reset(totalItems?), setItemsPerPage(n), setTotalItems(n), getCurrentPage(), getTotalPages(). O evento me-before-move é cancelável — preventDefault() impede a troca de página (equivale ao return false do beforeMove). 

pag.addEventListener('me-before-move', (e) => {
  if (temAlteracoesNaoSalvas) e.preventDefault(); // cancela a navegação
});
pag.movePageTo(3);

<me-sidebar> — Menu lateral

Espelha o Sidebar do app: recolhida 64px / aberta 288px (300ms), borda direita cinza, header 80px com logo "variant" + toggle rosa 24px, item ativo teal com texto semibold, hover teal a 8%. Clique no botão rosa para alternar (emite me-toggle). Como no app, não há "Sair" na sidebar (o slot="footer" existe para casos especiais).

Presets de menu

Os menus por perfil vivem dentro do componente, em components/sidebar-presets.js (fonte única de verdade) — você não declara itens no HTML. Basta escolher o preset e qual item está ativo (active-item, pela key do item). A seleção do preset é feita por você (seletor externo) — o componente não o renderiza. Com persist-key, a escolha é lembrada em localStorage entre reloads. Troque abaixo e recarregue para ver persistir. Emite me-preset-change (detail.name).

Preset: Gestor Médico 
<!-- Menus definidos em components/sidebar-presets.js -->
<me-sidebar expanded preset="gestor" active-item="aprovacoes"
            persist-key="me-bricks:sidebar-demo"></me-sidebar>

<script>
  const sidebar = document.querySelector('me-sidebar');
  sidebar.preset = 'medico'; // troca, persiste e emite me-preset-change
</script>

Para adicionar ou editar um menu (itens, ícones, rótulos), edite components/sidebar-presets.js — a mudança reflete em todos os protótipos que usam o me-sidebar.

<me-pages> + <me-page> — Controle de páginas

Roteador por hash (#/rota): transforma uma página estática num app multi-página, sem servidor nem build. Deep-link e voltar/avançar do navegador funcionam nativamente. Emite change (detail.page) e reflete a rota atual em me-pages[page]. Esta própria documentação usa o me-pages — cada componente do menu ao lado é uma rota. Veja também um exemplo de app completo em demo/pages.html. 

<me-pages default="inicio">
  <me-page name="inicio">...</me-page>
  <me-page name="escalas">...</me-page>
</me-pages>
